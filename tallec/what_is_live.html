Two of the three identifiers were each covering two different players, exactly as you said. All sixteen rows are loaded, the two Blake Moores and two James Walshes now have separate identities, and the database has a hard uniqueness rule so this class of problem cannot come back unnoticed.

The code was reviewed, and nine things were wrong

Worth telling you rather than quietly fixing.

I had the whole thing reviewed independently this week. Nine real problems came back. Every one was reproduced before being touched, and every one is fixed. The two worth knowing about:

The one that would have embarrassed us

The translation tool was advertised as taking a player's position, age and workload into account. It was not. A 20-year-old prop with four games and a 31-year-old fullback with 150 got the identical answer. The model that does that conditioning had been built and validated but never actually connected. It is connected now.

The second: three old scripts could still overwrite live data, and one of them computed ratings by pooling all four competitions into a single pot. They now refuse to run without an explicit override.

The rest were smaller — a file path that only worked on my machine, an unpinned dependency that could have broken the app on startup, and a squad simulator that was comparing a seventeen-man line-up against a thirty-man season squad, so its headline number partly measured squad size. All corrected and deployed.

I mention it because a system nobody has audited is not the same as a system that passed an audit, and you should know which one you have.

Three things I need from you

In order of how much each would change.

  1. NRL 2026 positions, the way the Super League master came This is the last position gap. The current NRL season's positions are estimated from players' other seasons rather than read off a team sheet, so a player who has changed role this year is measured against the wrong peers. One export with the position joined row by row closes it.

    How I will check it on arrival — the same four tests the first Super League file failed: average minutes per position (props around 46, wingers around 78), the spread of passes per minute (about thirty-fold, hookers highest), positions per player (around 1.5), and that the position column has no more values than the file has rows.

  2. Sign-off on the metric dictionary All 341 rows are still marked for review. Ten are flagged low confidence, and one — Charge Down — divides by something that is not in the data at all. Nothing in the Volume and Rate layer can be finalised until those denominators are agreed, and that is a rugby judgement rather than a statistical one.
  3. Team lists, even manually typed Everything about player availability is currently measured on the seventeen who actually played, which is only known afterwards. Friday-morning team sheets would turn it from a retrospective measure into something usable during the week. Nothing fancy needed — a list of names per club per round is enough.

What is deliberately not built

The player layer has been measured against the match model and it does help — by about a quarter of a point of margin error, which is real and small. Wiring it into the weekly prediction run is a decision to make once team lists exist, because without them it can only be measured after the fact.

One player, several positions

A player who covers hooker and bench gets one rating against his most common position. Rating him separately in each is on the list, and needs the NRL position data first.
